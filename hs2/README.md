把 `/Users/xiaofeng.zhao/myHs2` 的 HS2 捏人功能与模型迁移进 Godot 的成果。

## 目录

| 文件 | 作用 |
| --- | --- |
| `hs2/data/` | HoneySelect 原版捏人数据表（cf_customhead/body、cf_anmShapeHead/Body、bone_mappings.csv、face_bone_mappings.csv） |
| `hs2/model/` | 角色七部件（body/top/bot/shoe/head/hair_f/hair_b）+ Textures |
| `hs2/hs2_shape.gd` | 数据层：`shape.js` / `shape_data.py` 的 GDScript 1:1 移植（滑杆 0..1 → 骨骼增量） |
| `hs2/hs2_rig_merge.gd` | 骨架合并器：`rig_merge.js` 思路的 Godot 实现（单一骨架 + 统一蒙皮 + 接缝对齐） |
| `hs2/hs2_character.gd` | 装配层：加载七部件、合并骨架、应用捏人增量、滑杆 UI（脸部 66 项 / 身体 33 项） |

| `tools/fbx2glb.py` | Blender 批处理：把 HS2 的 FBX 转成 glb（Godot 的 ufbx 导入这些 FBX 会破坏 bind，必须走这条转换） |

## 关键实现要点（踩坑记录）

1. **FBX → glb**：直接用 Godot 导入 HS2 的 FBX 时，头模 bind 会错乱（网格被拉伸）。改用 Blender headless 转换 glb 后正常。
2. **网格朝向**：原始 glb 需在模型根节点加 `rotation_degrees = (180,0,0)` 才站立。
3. **Godot 蒙皮公式**（用 4 组候选公式实测判别）：`v_render = S · Pose(b) · bind(b) · v_mesh`，且实测 `bind(b) = rest(b)⁻¹`（静止时等于原网格）。
4. **合并骨架**：把 head/hair 的骨骼并入 body 骨架（184 → 289 骨），
   `rest_new(b) = A · rest_old(b)`，`bind_new(b) = bind_old(b)`（保持不变）。
5. **必须重映射顶点骨骼索引**（对应 JS 的 `remapSkinIndex`）：否则头/发顶点仍指向身体骨，表现为“头跑到脚底下”。
6. **头身接缝对齐**：A 由数据驱动求出——在蒙皮输出空间测量「身体脖颈顶端」与「头模底沿」，
   把头模底沿放到脖颈顶端下方 `NECK_OVERLAP = 0.05` 处，保证接缝吻合。
7. **头发朝向**：hair_f/hair_b 资产相对头部转了 180°（否则发髻盖脸），需额外绕竖直轴翻正。
8. **镜像骨骼**：HS2 骨骼含负缩放，重建 pose 时要用 `basis.determinant() < 0` 补回符号，
   无增量的骨骼直接用 `reset_bone_pose()` 回到 rest，避免整条链被转倒。

## 头发专项分析（第二轮修复）

第二轮把头发彻底对齐，结论如下（全部有实测数据支撑）：

1. **发色贴图是灰度图**（实测均值 RGB≈0.65，alpha≈0.8），发色完全由材质 `albedo_color` 决定 → 脚本里用 `HAIR_TINT` 染色，`alpha_scissor=0.35` 裁剪发丝。
2. **hair 的 bind 与 rest 不互逆**：身体满足 `bind = rest⁻¹`（静止渲染=原始网格），
   但 head/hair 不满足——实测毛发渲染结果相对原始网格被整体转了 90°（后发从「竖直 0.57 长」变成「朝后横躺 0.57」）。
   → 对头发改用 `rest = bind⁻¹`，使静止渲染回到原始网格方向（长发自然垂下）。
3. **原始网格帧与世界帧差一次 180°X**：改用 `bind⁻¹` 后头发虽然竖起来了，
   却是「朝上长」（世界 y 到 2.06，超过头顶），因为原始网格帧的上下与世界相反。
   → 在装配增量 A 里补 `Rx(180)`。
4. **发顶对齐**：旋转后按「发顶 = 头顶 + 0.01、x/z 取头部中心」平移，
   最终后发世界包围盒 y∈[1.25, 1.82]（从头顶垂到背部中段）、z∈[-0.31,-0.02]（在头后方），
   前发 z∈[0.02,0.11]（在脸前方）——与参考渲染一致。

用顶点云统计代替包围盒近似，修正了头部前后偏移：

| 测量项 | 修复前 | 修复后 |
| --- | --- | --- |

3. 令两者重合、且头底沿位于脖颈顶端下方 `NECK_OVERLAP = 0.05`。

### 4. 实现（唯一权威来源）
- `A_head = bone_p`（头骨 rest 在渲染空间的变换）；`A_hair = A_head · T(0,0.05,0) · Rx(-90°)`

## 头发对齐修复（与头部同一类问题：相对装配增量写错轴）

### 1. 从 golden 推导头发的相对装配增量
golden `head_ref.json` 给的是**各部件相对 cf_J_Head_s** 的矩阵：
- head：`R_gold = 0.01·I`（无旋转无平移）
- hair_f / hair_b：`R_gold = T(0, 0.05, 0)·Rx(-90°)·0.01`

⇒ 头发相对**头部**的局部关系 = `R_gold_head⁻¹ · R_gold_hair = T(0, 0.05, 0)·Rx(-90°)`
（在 **mesh 局部空间**，Blender 侧；这与 `app.js` 里 `HAIR_CORR = T(0,-0.05,0)·Rx(-90°)` 一致）。

换算到本工程坐标系（网格→渲染空间的轴转换 C = Rx(-90°)：(x,y,z)→(x,z,-y)）后，
**相对增量 = T(0, 0, +0.05) · Rx(-90°)** —— 平移是 **z 轴 +5cm**。

### 2. 之前的错误
代码里写成了 `T(0, +0.05, 0)`（**平移写在了 y 轴**），于是整套头发整体偏 5cm，
表现就是"头和脖子对齐了、头发没对齐"。

### 3. 验收（新增 A2 项，判据同样来自 Blender oracle + golden）
| 部件 | 实测相对头骨偏移 | oracle 期望 | 误差 |
| --- | --- | --- | --- |
| hair_f | (0.002, 0.063, 0.063) | (0.002, 0.063, 0.064) | **1 mm PASS** |
| hair_b | (0.003, −0.093, −0.009) | (0.004, −0.093, −0.010) | **1 mm PASS** |

期望值算法：Blender 导入 `hair_f.fbx / hair_b.fbx` 得独立世界 AABB 中心，
乘 golden 的 `T(0,0.05,0)·Rx(90)`，再减头骨位置。命令行 `-s tools/acceptance.gd` 可复跑。

> 教训：**头发不是"看着调"，它和头部一样有权威矩阵**；写错任何一轴都会整体偏移。
> 现在 head / hair_f / hair_b 三项都在 1mm 内，且都有机器判据。

### 为什么推倒重来（旧实现的根因）
旧版 `hair_physics.gd` 直接对**头发骨骼**做尾点 verlet，但本工程发骨的 rest 位置**根本不在头发几何上**。
实测（当时用 diag_hairmap 量的）：

| 骨 | 骨 rest 位置 | 它支配的顶点实际渲染位置 | 偏差 |
| --- | --- | --- | --- |
| `cf_J_hairBL_03` | (0.127, 1.755, 0.198) | (0.14, 1.38, 0.08) | **~40 cm** |
| `cf_J_hairBC_02` | (0.007, 1.512, 0.237) | (0.00, 1.29, -0.15) | **~40 cm** |

骨链朝「头顶后上方」走，头发却朝「下前方」垂 —— 于是绕骨头旋转顶点时**旋转中心不在头发上**：
静止看着还行（静止渲染恒为 `A·v_mesh`，与权重无关），一加风毛发就炸成放射状碎片。
旧截图 `phys_rest.png` 与 `phys_wind.png` 甚至**字节完全相同**，就是因为形变根本没落到头发上。

### 本实现（六步，全部有 headless 判据）

1. **从几何建链**：取每根发骨「所支配顶点」的质心作为链上关节，链序取骨骼层级序，再按弧长重采样成
   9 个关节 ⇒ 链真正躺在头发里。共 7 条导引链（前发 4 + 后发 3）。
   根关节取该骨顶点群里**最靠头顶的 5 cm** 质心，即「发际附着点」（前/后发分别是
   (0.003,1.764,0.037) 与 (0.002,1.769,-0.025)）。
2. **不伸缩链**：Verlet 积分 + 迭代距离约束；最后再做一趟「跟随领头」投影（从被钉死的根往下逐节重投影），
   链长**严格精确** —— 实测最大相对伸长 **0.0004%**。
3. **钉死根部**：根部每帧钉到「头骨位姿增量 × 静止根位」；同时把整条链按头骨（以及骨架整体）
   的位姿增量带过去并保留相对速度 ⇒ 转头/整体移动都有惯性甩动。
4. **与身体碰撞**：头用**头模 AABB** 拟合椭球（头骨原点其实不在头里，不能用骨位置！），
   颈/胸/腰用 6 个由身体顶点群实测半轴拟合的椭球，随骨骼 pose 刚体变换，并做距离粗筛。
5. **鸟群分离（boids separation）**：任意两条导引链的**同段质点**（|Δindex| ≤ 2）间距小于
   `boid_separation` 就各退一半 ⇒ 头发不互相穿插、也不黏成一坨。
6. **链条之间插值**：在相邻导引链之间按权重插值出**虚拟发链**（每对间隙 2 条，共 10 条）；
   再把网格顶点按「到各链条折线的距离」重新分配蒙皮权重（链内按投影位置混合相邻两关节），
   并在网格上做 3 轮权重平滑防止同一张发片被拆到两条链上。
   实测虚拟链真实驱动 **hair_f 534 / hair_b 984 个顶点**（不是摆设）。

### 为什么要重绑蒙皮（以及为什么安全）
本工程头发满足 `bind = rest⁻¹`（见 `hs2_rig_merge.gd` 的 `use_bind_inverse`），
所以**静止时任意归一化权重都渲染成 `A·v_mesh`** —— 换骨头 / 换权重都不会改变静止外观。
本实现据此新建「发链骨」：`global_rest = 关节静止位姿`、`bind = rest⁻¹·A`；
写回用 `Skeleton3D.set_bone_global_pose_override(bone, T, 1.0, true)` 直接写**全局**位姿
（实测本骨架的局部 `rest·pose` 合成在新建骨上不可靠，全局 override 精确）。
验收：装配检查 A2 项在重绑前后都是 **1 mm**（静止渲染未变）。

### 穿模修复（重点）：只把「链心」推出身体是不够的

第一版碰撞只约束**链条质点**，结果头发照样穿过头和身体。查下来是三个叠加的原因：

| 原因 | 现象 | 修法 |
| --- | --- | --- |
| **① 发片是「面」，离链心有几厘米** | 链心检测穿透 0.01mm，但**渲染出来的顶点**最深插进身体 **29mm / 37 个顶点** | 碰撞半径按**每个关节自己的发片厚度**取（该关节支配顶点到关节的距离分位数），而不是一个全局常数 |
| **② 碰撞体只覆盖了 7 处（头+脊柱）** | 胸、肩、上臂完全没有碰撞体 → 头发垂到胸前直接插进乳房/肩膀 | 碰撞体扩到 **19 颗椭球**（头/颈/脊柱/胸/腰/乳房/肩/上臂/前臂） |
| **③ 捏人滑杆改了身体，碰撞体没跟着变** | 把「头部大小/胸/腰」拉满后，身体变形而椭球不变 → 头发插进去 | 碰撞体保留骨骼 delta 的**缩放**（原先被 `orthonormalized()` 丢掉了）；滑杆变化时重建穿模候选集 |

最后再加一道**网格级修补**做兜底：预先挑出「静止时在体外、且离身体 18mm 以内」的顶点（实测 284 个），
每 2 个物理帧对这些顶点做一次**真实蒙皮计算**；谁的蒙皮位置插进身体，就按蒙皮权重把驱动它的链关节
往外交同样的位移，再重投影链长（不伸缩约束不能让位）。这样「看见的发片面」被直接约束住，而不是间接靠链心。

修复前后的实测对比（穿模 = 「静止时在体外、运动后插进身体」的蒙皮顶点）：

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 静止稳定 | 28.9 mm / 37 顶点 | **0.00 mm / 0 顶点** |
| 绕头中心转 45° | 13.3 mm / 2 顶点 | **1.35 mm / 1 顶点** |
| 风 25 m/s² | 27.5 mm / 10 顶点 | **1.68 mm / 1 顶点** |
| 滑杆全拉满 | 19.5 mm / 9 顶点 | **0.00 mm / 0 顶点** |
| 滑杆全拉满 + 风 25 | 39.6 mm / 16 顶点 | **0.00 mm / 0 顶点** |

> 剩下的 1mm 量级是「每 2 帧修补一次」带来的 1 帧延迟，肉眼不可见。
> 性能：整个求解 + 修补 **5.2 ms/物理帧**（实时运行 70~103 fps）。

### 浮空修复：碰撞半径不能用「发片的横向尺寸」

穿模修完之后出现新问题：**头发离开身体太远，像戴假发套**。原因是碰撞半径取错了量：

> 当时用「该关节支配的顶点到关节的**距离**」当半径 —— 那是发片的**横向尺寸**。
> 后发那几张发片很宽，中位距离直接顶到 25mm 上限，于是整条后发的链心被顶离背部 **25mm + 6mm 余量**。

正确的量是**「该关节的发片比关节本身更深入身体多少」**：

```
r_j = 分位数( max(0, signed_depth(顶点) − signed_depth(关节)) )
```

也就是「关节往外让出这么多，发片面就刚好贴住身体」。头发本来就贴着身体时这个值天然接近 0，
所以**贴体的头发不会被推开**，只有真正往身体里长的那部分发片才会让位。

修完后的实测半径（mm）：后发三条链是 `0 0 0 3 20 20 20 19 9`（只有真正贴背的那几节在让位），
前发是 `0 0 0 2 0 0 1 4 9`（几乎不让位）。

量化对比（统计**全部头发顶点到身体表面的距离**，看「<30mm 的贴体顶点」掉没掉）：

| | 旧（横向尺寸当半径） | 新（向内厚度当半径） |
| --- | --- | --- |
| 静止无物理时 <30mm 的顶点 | 183 | 183 |
| 物理稳定后 <30mm 的顶点 | **135（被推走 48 个）** | **177（只掉 6 个）** |

侧视图与「未开物理的原始静止几何」逐像素对比：差异 **0.33%**（等于没变），
也就是说现在物理稳定后的头发和资产原始贴体姿态基本一致。

同时把网格级修补加了**松弛系数 0.7**（一次只推 70% 穿透量）避免过冲抖动，
并把每个候选顶点的「最近几颗椭球」缓存下来、每 15 次修补刷新一次，
使整套求解 + 修补稳定在 **4.2 ms/物理帧**（中位值）。

## 头发外观：真实感着色 + 物理发链可视化

### 1. 头发改用 `shaders/hair.gdshader`（Kajiya-Kay 双叶各向异性）
之前头发用的是 `StandardMaterial3D`，仓库里的 `hair.gdshader` 根本没被用上。现在接上了，
并且为了让它与资产无关地成立，做了两件**建模期烘焙**：

| 烘焙进网格的东西 | 存哪 | 为什么 |
| --- | --- | --- |
| **发丝切线**（沿发链方向） | `ARRAY_TANGENT` | 旧版靠屏幕空间导数(dFdx/dFdy)从 UV 猜切线；但 HS2 发片的 UV 并**不沿发丝走**，猜出来的方向是错的。现在直接用发链方向当切线，UV 怎么排都不影响 |
| **根梢参数 + 朝内遮蔽** | `ARRAY_COLOR` 的 .r / .g | 与资产无关的根梢渐变与假 AO，换发模也成立 |

着色特性：双叶各向异性高光（主高光 + 次级偏移高光）、根梢渐变（`grad_curve` 控制发根保持深色的长度）、
根部压暗 + 朝内发片遮蔽、透光 backlight、双面渲染时翻转法线、发梢自动淡化（避免"被剪断"的硬边）、
包裹漫反射（头发不是平面，避免硬明暗交界）。

> 踩坑：把发色调暗时踩了一个坑 —— `hair_tint` 带 `source_color`，会被做 **sRGB→线性** 转换。
> 我把它设成 (0.40,0.28,0.19)，线性后只有 (0.13,0.06,0.03)，**漫反射几乎消失**，
> 于是高光一枝独秀，整片头发被冲成白色；而我当时误判成"高光太强"，越调越糟。
> 正确的做法是把 tint 放回 (0.72,0.55,0.40)（线性 ≈ 0.48，与旧材质同量级），
> 高光增益则要很小（`primary_gain 0.08 / secondary_gain 0.04`）——
> 因为 `LIGHT_COLOR` 已经含灯光能量（主光 1.6）。

### 2. 发链可视化开关（不渲染头发，只看物理链条）
面板「头发显示」三项：

| 选项 | 含义 |
| --- | --- |
| **头发网格** | 默认，只渲染头发 mesh |
| **仅物理发链** | 隐藏头发 mesh，把 17 条物理链条画成有宽度的发丝（导引链=琥珀金，插值链=钢蓝，向梢部渐细、亮度渐暗），并可选画关节标记 |
| **网格 + 发链** | 两者叠加，用来核对"发片有没有跟着链走" |

实现：骨架下挂一个 `ImmediateMesh`，每个物理帧把链条质点绕**视线方向**展开成 billboard 条带
（这样 1px 线宽限制被绕开，GL Compatibility 下也清晰可见）。发丝节点与头发网格同处骨架局部空间，
所以不需要任何坐标换算。

性能：网格模式与发链模式都实测 **115 fps**（`frame_time 10.9ms`）。

## 发链穿头修复 + 加密（第四轮）

### 1. 为什么链条会穿过脑袋
两个叠加的原因，都不是"碰撞没生效"，而是**碰撞体本身不对**：

| 原因 | 说明 |
| --- | --- |
| **① 头部碰撞体是 AABB 的「内接」椭球** | 内接椭球是内切的 —— 头模在鼻子/下巴/后脑/两侧这些方向上**超出它**。链心被推到椭球面后，仍然落在可见的头模里面。而且我第一版的"包含性自检"写错了：用 `max\|(v−c)/half\|` 逐轴比较，这个值对 AABB 恒 ≤1，等于什么都没验。正确的判据是**椭球范数** `\|(v−c)/half\|` |
| **② 钉死的根关节不参与碰撞** | `_solve_collision` 只处理 `j ≥ 1`，根部是 `_head_pose × q[0]` 硬钉的。如果静止时根就落在头里，整条链会**永远**从头里穿出来 |

**修法：**
- 头部碰撞体改成「**沿竖直方向切 5 段的椭球堆**」：每段只取该高度区间内的头模顶点拟合中心/半径，
  再按**该段顶点在这颗椭球里的最大范数**放大 —— 逐顶点归属，所以"包含性"是可验证的。
  构建时会打印 `头模 6737 顶点，未覆盖 0 个`。
- 新增 `_relax_rest_chains()`：在**建骨/算权重之前**，把静止发链的所有关节（含被钉死的根）
  先推出碰撞体一次。必须在建骨之前 —— 骨 rest 和蒙皮权重都是按最终链形算的。
  实测推出 **36 个关节，最大 97.4mm**（这些就是原来"从头里穿出来"的关节）。

### 2. 网格级修补的两个数学错误
排查过程中还揪出修补器自身的两处错，它们让"多链条"场景下修补基本失效：

| 错误 | 后果 | 修法 |
| --- | --- | --- |
| 关节位移写成 `Δ = w·dl`，少了 `1/Σw²` | 一个 0.5/0.5 权重的顶点**只被推了一半**；插值链越多、权重越分散，欠得越多 | 顶点位置 ≈ Σ w_k·关节位置，最小范数解是 `Δ_k = w_k·dl/Σw_k²` |
| 同一关节被多个顶点驱动时**直接累加** | 直接求和会过冲振荡（实测：把修补范围放宽后静止态反而从 0.4mm 恶化到 27mm，风停残差 199mm） | 先按关节取**平均**再乘松弛系数，每帧位移有界 |

### 3. 链条加密
`interpolated_per_gap: 2 → 3`、`joints_per_chain: 9 → 12`：

| | 之前 | 现在 |
| --- | --- | --- |
| 发链数 | 17（7 导引 + 10 插值） | **22（7 导引 + 15 插值）** |
| 链关节总数 | 153 | **264**（+73%） |

> 试过 `interpolated_per_gap = 4`（27 条 / 270 关节），但**穿透反而恶化到 32mm**：
> 插值链是两条导引链的混合，数量太多时网格顶点会被大量分配给"平均位置"，
> 而那个位置并不对应任何真实发片 —— 权重越分散，运动时越容易荡进身体。
> 所以链条数量不是越多越好，3 是比较合适的甜点。

### 4. 修复后验收

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 静止稳定 | 链条从头里穿出（36 关节 / 最深 97mm） | **网格穿透 1.78 mm / 2 顶点** |
| 绕头中心转 45° | 32.2 mm / 5 顶点 | **5.03 mm / 1 顶点** |
| 风 25 m/s² | 5.66 mm / 2 顶点 | **5.66 mm / 2 顶点** |
| 滑杆全拉满 | 15.5 mm / 3 顶点 | **6.61 mm / 3 顶点** |
| 滑杆全拉满 + 风 25 | — | **0.00 mm / 0 顶点** |
| 关闭物理 | — | **0.000 mm**（与静止几何完全一致） |
| 求解耗时 | 9.4 ms/帧 | **6.0 ms/帧** |

## 发链穿头：为什么"理论上不该穿模"却没做到（5 条必要条件逐条核对）

不穿模需要 5 个条件**同时**成立。逐条核对当前实现：

| # | 必要条件 | 实际状态 |
| --- | --- | --- |
| 1 | **碰撞体 ⊇ 网格，且与链条同空间** | ❌ 头部椭球用 `A_head = global_rest(Head_s)·bind(Head_s)` 变换头模顶点，但头模顶点绑在**面骨**上 ⇒ 椭球整体偏 **1.6m**（中心在 y≈0，头在 y≈1.66）。**等于没有头部碰撞**——这是"链条进脑袋"的第一位原因 |
| 2 | **每个粒子都要被检测** | ❌ `_joint_neighbours = 10`，碰撞体共 24 颗 ⇒ 每个关节有 14 颗没测（关节一动"最近 10 颗"就过期） |
| 3 | **碰撞是最后一个约束，或约束集迭代到收敛** | ❌ `_solve()` 原以 `_solve_lengths_exact()`（链长投影）收尾 —— 它沿链方向重投影，会把**刚推出去的关节重新拉回身体里**。反过来以碰撞收尾又会破坏"不伸缩"（实测 **361%**） |
| 4 | **静止预推不能把关节推进体内** | ❌ `_relax_rest_chains` 用椭球推挤，推挤方向可能指向头内 |
| 5 | **资产本身就长在头里的部分要"固定"，不是"推开"** | ❌ 发片内层本来就嵌在头皮里（资产设计如此），任何严格推挤都会把它扯出去 |

**已修**：1（椭球按真实蒙皮顶点拟合，落到 y 1.577~1.755 与头模 AABB 1.559~1.773 对齐）、
2（提到 12）、3（改成**交替迭代 3 轮 {碰撞 → 链长投影}**，两者同时收敛）、4（推完若落在头模内则撤销）、
5（实现了 `_compute_attachment`：从头往下、凡在头模内的关节判为**头皮固定段**，刚性跟随头骨、不参与物理）。

**剩下的第 5 条是资产层的客观事实，不是 bug**：

> 你在"仅物理发链"里看到的那段在头里的链条，**正是资产本来就画在头里的发片内层**。
> 用严格判据去推它，它必然被推出去 ⇒ 发型被扯开（实测静止漂移 **39~68mm**）。

所以"理论上不该穿模"要成立，必须先定义清楚"穿模"指哪一部分：
- 若指**可见外层**发片穿模 → 已解决（当前配置：静止漂移 4.4mm、风 0 穿透）；
- 若指**所有链关节**都在头模外 → 必须接受发型改变（按物理正确的位置重新定稿发根）。

当前 `head_mesh_collision = false`（默认关，因为开启会让发型变形）；打开后严格判据可从 173 降到 15~25 个关节在体内。

## 发链穿头：根因已定位（严格判据），修复未完成

### 1. 先做了「严格判据」——结论和椭球判据完全相反
之前所有碰撞验收都是拿**椭球**量穿透，报出来 0.01mm。这次加了不依赖任何近似的
**射线奇偶判据**（直接对 body+head 的三角形做内外判定，并用最近三角形给深度）：

| 判据 | 结果 |
| --- | --- |
| 椭球判据 | 全部关节在体外（0 mm） |
| **严格射线判据** | **264 个链关节里 173 个在 mesh 内部，最深 61.7 mm** |

### 2. 根因：头部碰撞体的坐标系错了 1.6 米
`_build_colliders` 里用 `A_head = global_rest(cf_J_Head_s) · bind(cf_J_Head_s)`
把所有头模顶点变换到"头骨空间"再拟合椭球。但**头模顶点实际绑在面骨上，不是绑在 Head_s 上**，
两者 bind 不同 ⇒ 拟合出来的椭球整体偏了约 **1.6m**（中心落在 y≈0，而头在 y≈1.66）。
也就是说：**此前根本不存在有效的头部碰撞**。

顺带还发现自己的"包含性自检"也写错了：用 `max|(v−c)/half|` 逐轴比较，这个值对 AABB **恒 ≤1**，
等于什么都没验。正确判据是椭球范数 `|(v−c)/half|`。

### 3. 正确的修法（已验证包含性，但未启用）
按 **rest 空间蒙皮顶点**（`global_rest(b)·bind(b)`，与链条同一个空间）沿竖直分带拟合椭球，
并标记 `static` 不参与 pose delta（头骨原点在 1.6m 外，用它带动整颗头本来就是错的）。
自检结果：**头模 6737 顶点，未覆盖 0 个**。严格判据随之从 173 降到 **9~18 个**。

**但没能落地**：改动会连锁改变「每关节发片厚度」与「穿模候选集」（377 → 831），
静止姿态漂移从 4mm 涨到 **80~115mm** —— 发型被扯变形。
根因是**发片内层本来就"长在头里"**（资产设计如此），强行把链条整段推出必然破坏发型；
静止预推位移实测可达 178mm。

### 4. 也试过完全基于网格的严格碰撞场（未采用）
在头发可达区域建体素场，对每根 (x,y) 列沿 +Z 打射线、按交点实体化（200ms 建好）。
但在这套网格上无论奇偶法还是带符号环绕数都有约 7% 的漏洞
（网格存在开放边界/绕向不一致），无法给出"绝不穿模"的保证，故默认关闭（`sdf_enabled=false`）。

### 5. 当前状态
已回退到「动起来正常、外观正常」的配置（静止 0.85mm、转头 0.94mm、风 0.51mm、求解 6.9ms/帧），
并在 `_build_colliders` 顶部写明了上述遗留问题。
**下一步建议**：把"发片内层在头里"当作合法状态 —— 只对**朝向身体外侧的发片面**做严格推挤，
而不是把所有链关节当作必须在外；或改成对网格做保守体素化（三角形栅格化 + 从边界 FloodFill），
而不是射线实体化。

## 发根固定模型（第五轮）：链条固定段 + 超出头皮才参与物理

按"发根固定在头顶、只有露出头皮的部分参与物理"重构：

- `_compute_attachment()`：对每条链**从根往下**逐关节判定是否还在头模网格内部，
  第一个走出去的关节之前的全部关节记为「头皮固定段」（`_attach[ci]`）。
  判定用**真实头模三角形 + 射线奇偶**（4cm 空间哈希加速），不用椭球 ——
  头部椭球把脸/下巴/脖子都包进去，会把"垂在脸前"的头发也判成头皮里。
- 固定段：每帧 `p[j] = _head_pose · q[j]`，刚性跟随头骨；`_integrate` / `_solve_lengths` /
  `_solve_lengths_exact` / `_solve_collision` / `_solve_boids` 全部跳过，插值链同理。
- 自由段：正常 verlet + 碰撞 + 鸟群。
- 长度约束的两端固定性也做了区分（两端固定→跳过；一端固定→只动自由端）。

**关键发现**：在链条自己的空间里，只有**根关节**真的落在头模内部（22 条链各固定 1 个关节）。
也就是说，"链条穿过脑袋"并不是链条几何在头里，而是——

> **链条/头发处于「rest 渲染空间」，而渲染出来的头/身网格处于「pose 空间」；
> 只要骨架 pose 不是单位阵，两者就错开。**

这解释了为什么之前几轮修修补补总是"按下一个、翘起另一个"：椭球判据、严格判据、
固定段判据各自在不同空间里工作。

**下一步（已尝试，结论如下）**：把链条与碰撞体统一到同一个空间。我按方案 2 实做了：

| 动作 | 结果 |
| --- | --- |
| 所有碰撞体统一到 rest 空间（`global_rest·bind`，与链条同空间） | ✅ 严格判据 **173 → 15~25** 个关节在体内，是历次最好 |
| 头部椭球按**真实蒙皮顶点**拟合 | ✅ 椭球中心落到 y 1.577~1.755，与头模 AABB(y 1.559~1.773) 对齐；包含性 0 未覆盖 |
| 头皮固定段判定（真实头模 + 射线奇偶） | ✅ 正确识别固定段 |
| **但整体外观** | ❌ **静止漂移 50~90mm，发型被推散**（见下） |

**为什么仍然失败**：碰撞体一旦"正确"，就会**如实地**把头发推离它当前所在的位置 ——
而这份资产的头发本来就贴着（甚至插进）头皮与身体。于是"碰撞正确"和"保持发型"直接冲突：
- 头部椭球比头模胖 ⇒ 贴头皮的头发被顶飞；
- 改成"只推真正在头模内部的点"（射线判定）后，漂移从 88mm 降到 53mm，但仍然不是原发型；
- 把网格级修补关掉、把发片厚度半径归零，都无法消除剩余漂移。

**结论**：这不是又一个参数问题，而是**需要设计决策**：
1. 接受发型改变（重新按"物理正确"的姿态来定稿发根）；
2. 或者保留发型，但把"穿模"重新定义为"**可见外层**发片穿模"，只约束外层（内层在头里是资产设计的一部分）；
3. 或者按本轮已实现的**头皮固定段**思路做到底：固定段严格贴头皮不参与物理（已实现），
   自由段用真实头模约束（已实现），只需再调 radii/候选集把漂移压回 10mm 内。

当前代码已回退到稳定版（静止 1.13mm / 转头 0.92mm / 风 1.04mm / 漂移 4.0mm / 求解 7ms），
上述所有机制都保留在代码里（`_compute_attachment`、`_point_in_head`、体素场），默认关闭或按旧路径走。

### UI 可调
`启用 / 刚度 / 阻尼 / 重力 / 风力 / 鸟群分离 / 碰撞半径×`，面板实时显示
「拉伸 % · 链间距 mm · 穿透 mm/顶点数」（穿透按真实蒙皮顶点统计）。

> 踩坑记录：① 发骨 rest 不在几何上（本次根因，旧实现整条思路作废）；
> ② 本骨架局部 `rest·pose` 合成对新建骨不可靠 → 改用全局 pose override；
> ③ 碰撞体逐点求 `Basis.inverse()` + 双重循环鸟群 → 物理帧 24.5 ms；改为预求逆矩阵 + 距离粗筛 + 邻域遍历后降到基线以下；
> ④ 末趟长度投影必须「跟随领头」，否则 8 次迭代后仍有 8.6% 拉伸；
> ⑤ **穿透指标必须量「蒙皮后的网格顶点」而不是链质点**（链心 0.01mm vs 网格 29mm，差 3 个数量级，只看链心会误判成"没穿模"）；
> ⑥ 碰撞热路径里逐点求 `Basis.inverse()` + Dictionary 查表 → 单帧 15ms；改成扁平数组 + 每关节只测最近 6 颗椭球后回到 5ms；
> ⑦ **别把碰撞后的位置交给链长投影前不做碰撞**——链长投影会把人推回身体里；顺序必须是「约束 → 碰撞 → 修补 → 链长」；
> ⑧ **碰撞半径要用「向内厚度」而不是「横向尺寸」**：用过横向尺寸会把整条头发顶离身体（后发中位距离直接顶满上限 25mm）；
> ⑨ 性能计时必须取**中位数**——本机（Intel Iris）单次读数在 4~17ms 之间乱跳，最初被噪声误导过两轮。

## 第十轮：头发改用 C++ XPBD 插件，删除 HS2 自实现发链

**动机**：`hs2/hair_system.gd` 是 HS2 自实现的一套 GDScript 发链（导引发链 + 不伸缩约束 +
19 颗身体椭球 + 鸟群分离 + 链条插值 + 网格级穿模修补）。它堆了五轮补丁，根因（
链条在 rest 渲染空间、网格在 pose 空间）始终没解决。与此同时 `addons/cloth_native`
里已经有一套**跑通并验证过**的 C++ XPBD 头发/布料（测试场景
`scenes/simple_hair_demo.tscn`、`scenes/cloth_hair_test_suite.tscn` 在用）。

**本轮的决策**：不再修补 GDScript 那套，**整体删除**，捏人场景改用插件。

| 动作 | 结果 |
| --- | --- |
| 删除 `hs2/hair_system.gd` | 连同 `.uid` 一起删；`hs2_character.gd` 里所有引用（建链、UI、metric、rebuild_candidates）全部移除 |
| 头皮采样搬进插件 | `set_scalp_mesh(verts)`：调用方只交头模顶点云，插件内部完成球坐标网格采样 → 面部区剔除 → 最远点采样选束 → 按区域分配发长 |
| 发根跟随 | 每帧 `A = S·pose(头骨)·rest(头骨)⁻¹` 把静止发根映射到世界，`follow_skeleton()` 带位移与惯性速度 |
| 布料 | `XPBDClothNative` 连衣裙（腰头钉 2 行，半径按身体实测腰/髋/裙摆插值） |

### 踩到的坑（都是"看起来对、结果是秃顶/糊脸"那一类）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| ① | 头发渲染成**死黑的深蓝** | 发片网格没写 `ARRAY_NORMAL`，Godot 拿到零法线，只剩环境光 | `_build_render_strands` 里算面法线（切向 × 横向）写进 `ARRAY_NORMAL` |
| ② | **秃顶**（头顶整块没头发） | 极角 `phi` 从 0.18 起采样，发旋那一圈根本没被采到 | `phi` 从 0 起 |
| ③ | 仍然秃顶，且发丝从皮肤里钻出来 | 用"方向最一致的头模顶点"取表面点，`phi≈0` 的整圈会**全塌到同一个发旋顶点** | 改取沿 `dir` 的**支撑点**（凸包在该方向的最远点）`r = max_i (v_i−c)·dir`，再吸附到最近的真实顶点 |
| ④ | 发根全被吸到一根假想球上，渲染只剩一块窄板 | `_build_render_strands` 先按 golden 球面把 `rr_roots` **填满**了，后面"从头皮发根细分"的 while 循环一次都没进 | 头皮模式下**不再**预填球面点，直接以每根导向发根为中心绕法线铺开 |
| ⑤ | 发丝全长到**脸前面**，整张脸被盖住 | "脸朝向"用"离头心竖轴最远"自动识别 —— 后脑（枕骨）比鼻尖凸，前后判反了 | 改成显式参数 `set_face_dir()`，工程里按 HS2 约定传给 `+Z` |
| ⑥ | 前额顶部那撮径直扑到脸上 | 发旋处重力切向退化成 0，退化分支退回"径向朝外"（正好朝前） | 退化时直接用"向后"；并把向后偏置加权（`back_amt = 0.55 + 0.45·front`） |
| ⑦ | 静态摆好之后脸还是被一道"帘子"挡住 | 发根初始方向只决定**起始形状**；物理跑稳定后重力照样把前额那撮拉直垂在眼前 | 加**脸部挡板** `set_face_guard()`：眉毛高度以下、脸宽以内、位于颜面前方的粒子，求解阶段一律推回脑后并吃掉朝向脸的速度 |
| ⑧ | 刘海与长发交界处"一撮突然变长" | 刘海是 `bool` 硬切，边界上长度跳变 | 改成连续量 `bangness = front × 高度窗`，发长 `× (1 − 0.55·bangness)`，方向再 `lerp` 到侧向梳开 |
